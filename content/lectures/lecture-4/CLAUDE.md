## Facts worth not re-deriving

- CSS came out of **CERN**, not MIT. (Håkon Wium Lie, 1994.)
- `:first-child` is a **pseudo-class**, not a pseudo-element — the deck used to
  file it under the wrong heading.
- The property value is `white-space: nowrap`, not `no-wrap`.
- The colour function is `hsl()`, not `usl()`.
- CSS has **no `//` comments**. Every sample uses `/* … */`. If a snippet here
  contains `//` it is a bug, not SCSS.
- The deck deliberately does _not_ say "CSS3/CSS4"; CSS is versioned
  per-module and has been since CSS 2.1. "On the Way" lists newer features
  (anchor positioning, view transitions, scroll-driven animations, `@scope`)
  without claiming their support status — check Baseline before promoting one.
- Every claim added in the rewrite was run in headless Chrome 156:
  `hsl(34 100% 50%)` and `rgb(255 145 0)` both compute to `#ff9100`; a later
  `@layer` beats an id in an earlier one, and unlayered rules beat all layers;
  `:where()` adds 0 specificity, `:is()` takes its most specific argument;
  `flex: 1` = `1 1 0%`, `auto` = `1 1 auto`, `none` = `0 0 auto`;
  `display: flow-root` grows a parent around a 50px float (0px without);
  `margin-inline-start` / `border-inline-start` land on the right under
  `dir="rtl"`; `light-dark()` follows `color-scheme`; nesting with `h2`, `&:hover`,
  `.dark &` and a nested `@media` all apply; an unknown declaration (`colour`)
  is skipped while the rest of the rule applies; `@import … layer(x)` parses.
- Live demos inject `<style>` into the whole deck, so every new one is scoped
  under an `sd-*` class (`.sd-comb`, `.sd-cq`, …) while the code block shows the
  unscoped rule. Scoping adds one class to every selector equally, so the
  outcomes are unchanged. Do not use `.box` as a demo class: `lecture.scss`
  already styles it.
- `@layer` has no live demo on purpose: the deck's own CSS is unlayered, so it
  would beat any layered demo rule.

## Real-World Examples

One vertical stack of twelve components, each with its CSS, its HTML and a
live render in a light frame (`.sd-rw`): navigation bar (with the unstyled
HTML above it), buttons, card, product grid, page layout, form field, toggle
switch, alerts, data table, chat bubbles, breadcrumbs, notification badge.

- The code blocks are the exact text that runs. Each slide's `<style>` nests
  the shown CSS under a doubled scope (`.sd-card.sd-card { … }`), and the
  frame holds the shown HTML verbatim. The only hidden CSS is the frame itself
  and `.sd-rw.sd-rw :where(*) { all: revert }`, which strips the deck's
  reveal styles (lists, headings, `img` borders) so the frame renders like a
  plain page. The doubled class gives (0,2,0), enough to beat reveal's
  `.reveal ul li`-style rules, and every nested example rule outranks it.
- Do not edit one side only. The slides were generated by a throwaway script
  from one definition per example; if you change a sample, change the code
  block and the `<style>`/frame together and re-render.
- Measured in headless Chrome 156: product grid `minmax(90px, 1fr)` gives
  2 columns in the 240px frame and 4 in the 440px one; the page layout is one
  200px column in the 200px frame and `110px 306px` areas in the 420px one;
  the email field holding `parham@` is invalid, gets the red border and shows
  the error, the empty name field does not, and typing a valid address hides
  it; the checked switch is green with its knob at `translate: 20px`; even
  table rows are `#e5e7eb` and `.num` is `text-align: end`; `.me` bubbles sit
  flush right; `li + li::before` gives `›` on all but the first crumb; the
  badge sits 4px above and 10px past its icon; the disabled button is at
  `opacity: 0.5`.
- `:not(:placeholder-shown)` (not `:user-invalid`) is used on the form slide
  so the prefilled invalid email shows its error without interaction.

`cascading.svg` replaced `cascading.png` and its source
`diag/cascading.drawio`, the deck's last draw.io diagram. Order, weakest first:
Browser default, User, External 1…n (`<link>`), Internal 1…2 (`<style>`),
Inline. User sits below the author sheets because normal user styles lose to
author styles; only user `!important` beats them (CSS Cascade 4 §6.2 — headless
Chrome has no user sheet, so this one is from the spec). External below
internal is **only document order**, and only after specificity ties: in
Chrome 155, a `<style>` placed before a `<link>` lost to it, and with
`<link>`, `<link>`, `<style>`, `<style>` the last `<style>` won and
`style=""` beat all four. A browser default (`b` is bold) lost to an author
`b { font-weight: 400 }`. The drawing says all of this, so the side paragraph
was removed. It agrees with `cascade-order.svg` (browser < author < author
`!important`; `style=""` beats every selector).

The fish chart `specifishity.png` was removed: it used the old 4-part notation
that counts `style=""` and `!important` as specificity digits, which contradicts
`specificity.svg`.

## Positioning facts (measured in headless Chrome)

- With no positioned ancestor, an absolute box uses the **initial containing
  block**, not `<html>`. Test: `html { margin-left: 100px; height: 300px }` in
  an 800-wide window; `position: absolute; left: 0; bottom: 0` landed at x = 0
  and at the viewport bottom (513), not at the html box (x = 100, bottom 310);
  `width: 50%` gave 400, half the viewport, not half of html (700).
- Relative positioning keeps the **border box plus margin** in flow: a
  relative `div` (`height 20, padding 5, border 10, margin 7`, `top: 100px`)
  left the next sibling at 30 + 50 + 7 = 87.
- `position` applies to **all elements**: a relative inline `span` stayed
  `display: inline` and moved by its `left: 20px`.
