Why CSS?

  • HTML describes structure: headings, paragraphs, lists, forms
  • In the 90s, presentation was written into the HTML itself

<!-- 1996 style: <center> and <font> are obsolete in HTML today -->
<center><font size="7" color="red">Welcome</font></center>
  • CSS (Cascading Style Sheets) moves presentation out of the HTML
    • One stylesheet styles every page of a site, and is cached once
    • The same HTML can look different on a phone, on paper or in dark mode
    • Without CSS, the browser uses its own default styles

A Short History

  • Proposed by Håkon Wium Lie at CERN in 1994
  • CSS1 (1996), CSS2 (1998), CSS 2.1 (2011)
  • After 2.1, the language is split into modules (Selectors, Flexbox, Grid, Color, …), each with its own level
    • So there is no CSS3 or CSS4 release: browsers ship features one at a time
    • Before you use a feature, check that it is Baseline (works in every major browser) on MDN, or look it up on caniuse.com

Anatomy of a Rule

Values

  • Keywords: left, bold, none, auto, …
  • Colors: the same orange in four notations (the third is half transparent) 

color: #ff9100;               /* hex: rr gg bb */
color: rgb(255 145 0);        /* red green blue, 0 to 255 */
color: rgb(255 145 0 / 50%);  /* ... and 50% opacity */
color: hsl(34 100% 50%);      /* hue, saturation, lightness */
  • oklch() is the modern choice for palettes: equal steps in lightness look equal to the eye
  • Lengths: px, rem, %, vw, … (in Responsive Design)

Three Ways to Add CSS


<!-- 1. External: one file for the whole site (use this) -->
<link rel="stylesheet" href="style.css" />

<!-- 2. Internal: rules for this page only -->
<style>
  h1 { color: #ff9100; }
</style>

<!-- 3. Inline: one element, no selector -->
<h1 style="color: #ff9100">Hello</h1>
  • External sheets are cached and shared by every page
  • Inline styles are for one-off exceptions, or values set by JavaScript
  • type="text/css" is the default: old code writes it, you do not need to

Print Styles

  • A stylesheet can apply to one media type: screen, print or all 

<link rel="stylesheet" href="print.css" media="print" />
  

/* or inside any stylesheet */
@media print {
  nav, video, .ads { display: none; }
  a[href]::after { content: " (" attr(href) ")"; }
}
  • Try it: Ctrl/Cmd + P on any page, or emulate print in DevTools

:is(), :where(), :not()


/* instead of h1 a, h2 a, h3 a */
:is(h1, h2, h3) a { color: inherit; }

/* the same matching, but zero specificity: easy to override */
:where(ul, ol) { padding-left: 1.5rem; }

/* everything except */
button:not(:disabled):hover { background: #ff9100; }
  • :is() counts as its most specific argument
  • :where() always counts as 0: good for defaults in a library

:has(): the Parent Selector

  • Select an element by what it contains

label:has(input:checked) { background: rgb(118 255 3 / 25%); }

.card:has(img) { display: grid; grid-template-columns: 120px 1fr; }

form:has(:user-invalid) button { opacity: 0.5; }
  • Until :has(), this needed JavaScript; now it works in every major browser

Conflicting Rules

  • Several rules can set the same property on the same element

/* style.css */
p { color: red; }

/* <style> in the page */
p { color: blue; }
  • The cascade picks one value, by comparing in order:
    1. Origin and importance (browser, user, author, !important)
    2. The style="" attribute
    3. Cascade layers (@layer)
    4. Specificity of the selector
    5. Order of appearance: the later one wins

  • !important beats style="", and only another !important can beat it
  • Treat it as a last resort: lower the specificity or use a layer instead
  • An inherited value never wins, even if it was !important: a rule on the element itself beats it

Cascade Layers

  • @layer sets the order of whole groups of rules, so a later layer wins whatever the specificity 

@layer reset, framework, components;  /* the order is set here */

@import url("bootstrap.css") layer(framework);

@layer components {
  .link { color: #76ff03; }   /* wins */
}
@layer framework {
  #nav a { color: #ff5252; }  /* an id, but in an earlier layer */
}
  • Rules outside any layer beat every layer
  • No more !important wars with a framework: put it in a low layer

Inheritance

  • Some properties pass from parent to child, others do not
    • Inherited: color, font-*, line-height, text-align, visibility
    • Not inherited: margin, padding, border, background, width, display
  • Keywords for any property: inherit, initial, unset, revert

CSS Box Model

Each HTML element is a box: content, padding, border and margin

box-sizing: border-box

  • By default, width is the content only: padding and border are added on top
  • With border-box, width is the visible box: a 200px box stays 200px 

/* the first lines of almost every modern stylesheet */
*, *::before, *::after {
  box-sizing: border-box;
}

Layout Today

  • Normal flow first: blocks stack, inline content wraps
  • Flexbox for one direction: a nav bar, a row of buttons, centering
  • Grid for two directions: the page, a gallery, a form
  • position for things on top: a sticky header, a badge, a dialog
  • Floats: before flexbox and grid, they were the layout tool; today, only for wrapping text around an image

The display Property

  • block, inline: the two kinds of box in normal flow
  • inline-block: sits in a line, but takes width and height (the pre-flexbox trick for rows of boxes)
  • flex, grid: the element lays out its children
  • none: the element is not rendered at all

Static Positioning

  • The default position of HTML elements is static.
  • Static elements are positioned according to the normal flow of the page.
  • They are not affected by top, left, bottom, and right values.

Relative Positioning

  • A relative positioned element is positioned relative to its normal position
  • The reserved space (box model: content + padding + border + margin) for the element is still preserved in normal flow
  • Position is specified by top, left, right, bottom properties, e.g.,
    • top: +20px
    move the element 20px downward
    top: -20px
    move the element 20px upward
    bottom: -20px
    move the element 20px downward
    bottom: +20px
    move the element 20px upward

Absolute Positioning

  • An absolute position element is positioned relative to the first parent element that has a position other than static
    • If no such element is found, the containing block is the initial containing block: a viewport-sized rectangle, not the <html> element
  • Absolute positioned elements are removed from the normal flow
    • The document and other elements behave like the positioned element does not exist (no space for content, padding, border, margin)
    • The positioned elements can overlap other elements
    • Position is specified by top, left, right, bottom properties

Fixed Positioning

  • An element with fixed position is positioned relative to the browser window
    • Its position does not change by scrolling the page
    • Very useful for menus
  • These elements are removed from the normal flow
    • The document and other elements behave like the fixed positioned element does not exist (no content, padding, border, margin)
    • Fixed positioned elements can overlap other elements
  • Position is specified by top, left, right, bottom properties

Sticky Positioning

  • This one is somehow a combination of relative and fixed positions.
  • A sticky element acts like it's relatively positioned until it's scrolled to a certain threshold. After that, its position becomes fixed (e.g. after scrolling for 20px, it will be fixed on the page).
  • You must at least specify one of top, left, bottom or right for sticky to work.

Floats

  • A float moves to the left or right, and the text of the following content wraps around it
  • A parent with display: flow-root grows to contain its floats (it used to take a clearfix hack) 

img { float: left; width: 120px; margin-inline-end: 16px; }
.article { display: flow-root; }
Tux has been the Linux mascot since 1996. The text of this paragraph wraps around the floated image, and the border of the parent goes around both, because the parent has display: flow-root. Without it, the parent would end after the text and the image would hang out of it.

Grid

  • Two-dimensional layout model
    • Divides a page into major regions, defines the relationship in terms of size, position, and layer, between parts
  • Grid vs. Tables
    • Like tables, enables to align elements into columns and rows
    • However, many more layouts are possible
    • E.g., child elements could position themselves so they actually overlap

Defining a Grid

The container declares the tracks, and the children fall into them in order. 

      
        .container {
          display: grid;
          grid-template-columns: 200px 1fr 1fr;
          gap: 16px;
        }
  • fr is a fraction of the leftover space, so the columns above are fixed, half, half
  • gap replaces the margin tricks that floats needed

Repeating Tracks

      
        .container {
          display: grid;
          grid-template-columns: repeat(3, 1fr);
        }

A responsive gallery, with no media query at all: 

      
        .gallery {
          display: grid;
          grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
          gap: 16px;
        }
  • Fit as many 200px columns as possible, then share what is left

Placing Items

An item can span tracks, by line number or by name.

      
        .hero {
          grid-column: 1 / 3; /* from line 1 to line 3, so two columns */
          grid-row: 1;
        }

Or describe the layout as a picture:

      
        .page {
          display: grid;
          grid-template-areas:
            "header header"
            "side   main"
            "footer footer";
        }

        .page > nav { grid-area: side; }

Responsive Design

Responsive Design is the practice of making sure your content looks good on all screen sizes.

Everything in the website including layouts, fonts and images should automatically adapt to the user's device.

The Viewport Meta Tag


<meta name="viewport" content="width=device-width, initial-scale=1" />
  • Without it, a phone lays the page out 980px wide and shrinks it to fit: tiny text, and your media queries never match
  • With it, the layout width is the device width: the first line of every responsive page

Units

px borders, shadows, small fixed sizes
rem font sizes and spacing: the root font size (16px by default), so it follows the user's font setting
em the element's own font size
% a share of the parent (for width)
vw / vh 1% of the viewport width / height
dvh like vh, but follows the phone's address bar as it hides
ch the width of 0: max-width: 65ch keeps lines readable
fr a share of the leftover space in a grid
cm, mm, in, pt physical units, only meaningful on paper (1in = 96px)

Media Queries

  • Apply a block of rules only when a condition is true

@media (width <= 600px) { ... }          /* range syntax */
@media (max-width: 600px) { ... }        /* the same, older syntax */
@media (600px < width < 1000px) { ... }

@media (orientation: landscape) { ... }
@media (hover: hover) and (pointer: fine) { ... }  /* a mouse */
@media print, (width >= 1200px) { ... }           /* comma = or */
  • Media types today: all, screen, print; the others (tv, handheld, speech, …) are deprecated

Mobile First

  • Write the small-screen layout first, then add columns as the screen grows 

.cards {
  display: grid;
  gap: 1rem;  /* one column on a phone */
}

@media (width >= 600px) {
  .cards { grid-template-columns: 1fr 1fr; }
}

@media (width >= 1000px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}

Sizing Without Breakpoints

  • clamp(min, preferred, max) picks the preferred value, but never leaves the bounds 
      
        h1 {
          font-size: clamp(1.5rem, 4vw, 3rem);
        }
  • The heading grows with the viewport, stays readable on a phone, and stops growing on a projector
  • min() and max() work the same way

Custom Properties

  • CSS has variables, and unlike a preprocessor's they live in the browser
  • They cascade and inherit, like any other property
      
        :root {
          --brand: #ff9100;
          --gap: 16px;
        }

        .button {
          background: var(--brand);
          padding: var(--gap);
        }

Why It Matters

  • A variable can be redefined for a subtree, so one declaration re-themes everything below it
  • It can be read and written from JavaScript, which a preprocessor variable never can 
      
        .dark {
          --brand: #ffcc00;
        }
      
    
      
        element.style.setProperty("--brand", "#00e5ff");

Nesting


.card {
  padding: 1rem;

  h2 { margin: 0; }                         /* .card h2 */
  &:hover { outline: 2px solid #ff9100; }  /* .card:hover */
  .dark & { background: #222; }            /* .dark .card */

  @media (width >= 600px) {
    padding: 2rem;
  }
}
  • & is the parent selector; it is needed when the nested part is not a separate descendant
  • Native in every major browser: one of the main reasons people used Sass

Modern Color


:root {
  color-scheme: light dark;  /* also gives inputs and scrollbars a dark look */
  --brand: oklch(72% 0.19 55);
}

body {
  background: light-dark(#ffffff, #121212);
  color: light-dark(#222222, #eeeeee);
}

.button:hover {
  background: color-mix(in oklch, var(--brand), black 20%);
}
  • light-dark() picks the first value in light mode, the second in dark mode
  • color-mix(): a darker or lighter shade without a second variable

CSS Functions

  • Math: calc(), min(), max(), clamp()
  • Variables: var(--name, fallback)
  • Color: rgb(), hsl(), oklch(), color-mix(), light-dark()
  • Images: url(), linear-gradient(), radial-gradient()
  • Transforms: translate(), rotate(), scale()
  • Grid: repeat(), minmax()

.sidebar { width: calc(100% - 2 * var(--gap)); }

Transitions

  • Animate the change between two states, e.g. on hover

.button {
  background-color: #00e5ff;
  transition: background-color 200ms ease, transform 200ms ease;
}
.button:hover {
  background-color: #ff9100;
  transform: translateY(-4px);
}

Animations


@keyframes slide {
  to { transform: translateX(260px); background-color: #00e5ff; }
}
@keyframes spin {
  to { transform: rotate(360deg); }
}
.slide { animation: slide 2s ease-in-out infinite alternate; }
.spin  { animation: spin 3s linear infinite; }
  • Animate transform and opacity: changing left or width makes the browser redo the layout on every frame

Hiding Elements

display: none not rendered, takes no space, not read by screen readers
hidden attribute the same, from HTML
visibility: hidden invisible, keeps its space
opacity: 0 invisible, keeps its space, can still be clicked 

/* hidden on screen, still read by screen readers */
.visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
}

On the Way

  • Already in every major browser and covered above: :has(), @container, nesting, @layer, light-dark()
  • subgrid: a child lines its own items up on the parent's grid tracks
  • Newer; check Baseline before you rely on them:
    • Anchor positioning: place a tooltip next to its button in CSS
    • View transitions: animate between two pages or two states
    • Scroll-driven animations: tie an animation to the scroll position
    • @scope: limit rules to one part of the page

Browser DevTools

  • F12 or Cmd + Option + I, then the Elements panel
    • Styles: every rule that matches, in cascade order; a crossed-out declaration lost; edit values live
    • Computed: the final value, and which rule set it
    • The box model drawn with real numbers
    • flex and grid badges draw the tracks over the page
  • Device toolbar (Ctrl + Shift + M): try phone sizes
  • Rendering: emulate print, dark mode, reduced motion

CSS Tools

  • Reference: MDN (with Baseline status) and caniuse.com
  • Format and lint: Prettier, Stylelint; the W3C CSS validator
  • Preprocessors: Sass gave CSS variables and nesting years before browsers did; most of that is native now
  • Vendor prefixes (-webkit-, -moz-): needed for new features in the past; Autoprefixer adds the few still required
  • Frameworks: Tailwind (utility classes), Bootstrap (ready components); they are easier to use once you know the CSS under them
